# 本地图片 OCR 设计

## 目标

为兜兜拼音增加“拍照提取文字”和“上传图片提取文字”能力。第一版采用纯前端本地 OCR，图片只在浏览器中处理，不上传到服务器或第三方服务。

成功标准：

- 手机端可以调起后置摄像头拍照。
- 手机和电脑均可以选择 JPG、PNG、WebP 图片。
- 识别过程展示明确进度，且不阻塞页面主线程。
- 识别结果可先校对，再由用户确认写入正文。
- 当前正文非空时不会被静默覆盖。
- OCR 失败不会影响手工输入、PDF 导入和现有注音流程。

## 范围

### 本期包含

- 单张图片拍照或上传。
- 图片类型、文件大小和空结果校验。
- 按需加载 Tesseract.js 及简体中文识别数据。
- 本地识别进度、成功状态和错误状态。
- 可编辑的识别结果。
- “替换正文”与“追加到正文”两个明确操作。
- 回填后切换到单行模式，并将稿件标记为未保存的新版本。

### 本期不包含

- 云端 OCR、AI 视觉模型或后端接口。
- 多图批量识别。
- 图片裁剪、透视矫正和手动旋转界面。
- 手写文字专项识别。
- 原图或识别结果的服务端存储。
- 自动生成注音；用户仍需点击现有“生成注音”操作。

## 用户流程

1. 用户在正文区域附近打开“图片识字”卡片。
2. 用户选择“拍照识别”或“上传图片”。
3. 浏览器读取图片并开始本地识别。
4. 界面显示模型加载和识别百分比。
5. 识别完成后，结果显示在独立文本框中，用户可以校对。
6. 正文为空时，用户点击“填入正文”；正文非空时，界面提供“追加到正文”和带警示语义的“替换正文”。
7. 写入后保留现有生成注音、保存历史和打印流程。

## 架构

### `src/lib/image-ocr.ts`

负责与 Tesseract.js 交互：

- 动态导入依赖，避免进入主包首屏。
- 创建 `chi_sim` worker。
- 把 Tesseract 的状态映射为统一进度。
- 识别结束或失败时终止 worker。
- 仅返回原始识别文本，不擅自修正文意。

### `src/lib/image-import.ts`

负责不依赖浏览器 UI 的纯逻辑：

- 支持的 MIME 类型和最大文件大小。
- 文件校验及中文错误信息。
- OCR 文本的换行和首尾空白清理。
- 追加正文时的段落分隔规则。

纯逻辑单独测试，避免组件测试依赖真实 WASM 模型。

### `src/components/ImageOcrImport.tsx`

负责用户交互和临时状态：

- 两个独立文件输入：拍照输入使用 `capture="environment"`，上传输入不带 `capture`。
- 文件名、识别进度、结果草稿和错误状态。
- 调用 OCR 封装。
- 把确认后的文字写入 `useEditorStore`。

OCR 临时状态不进入全局 store，与现有 `PdfImport` 的边界保持一致。

### 页面接入

组件放在输入列中、靠近 `PdfImport`。图片 OCR 与 PDF 导入是并列导入方式，不改现有正文编辑器契约，也不修改 `src/lib/types.ts`。

## 数据与隐私

- 图片通过浏览器 `File` 对象直接交给本地 OCR worker。
- 不发起图片上传请求，不保存原图。
- 中文训练数据首次使用时需要下载；后续是否命中缓存由浏览器决定。
- UI 明确标注“图片仅在本机识别”，避免用户误解。

## 错误处理

- 非支持格式：提示选择 JPG、PNG 或 WebP。
- 文件过大：提示压缩或重新拍摄。
- 初始化或识别失败：保留当前正文和已有识别结果，允许重试。
- 没有识别出文字：提示调整光线、距离和角度后重拍。
- 用户再次选择图片：开始新任务并清空上一次任务错误。

## 测试

- 单元测试覆盖文件类型、大小、空文本、文本清理和追加规则。
- 组件测试通过 mock OCR 封装验证：
  - 上传后展示进度与结果。
  - 正文为空时填入。
  - 正文非空时追加或替换。
  - 失败时不改正文。
- 全量执行 `npm test`。
- 执行 `npm run build`，验证 Tesseract.js 动态加载和 TypeScript 构建。

## 风险与控制

- 中文模型体积较大：只在首次使用时动态加载。
- 手机性能差异较大：一次只处理一张图片，并展示真实进度。
- OCR 可能错字：结果必须经过可编辑校对区，不自动进入生成流程。
- 浏览器拍照行为不完全一致：使用标准文件输入与 `capture` 提示；不承诺自建实时相机界面。
