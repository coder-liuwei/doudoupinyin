# 更新日志页面设计

## 目标

为老师、家长等普通用户提供一个易读的产品更新日志，记录每次发布中用户能够感知的新功能、体验优化和贡献人。

首版不从 Git 提交自动生成内容，也不提供后台录入界面。更新记录作为前端静态数据随代码发布，以保证文案对用户友好，并保持实现简单。

## 页面与入口

- 新增 `/changelog` 路由。
- 在主页顶部标题区右侧放置“更新日志”入口；移动端跟随现有标题区布局自然换行。
- 更新日志页左上角仅保留“← 返回拼音工具”，链接回 `/`，不显示重复的“兜兜拼音”品牌文字。
- 页面标题为“我们又进步咯”。
- 标题区说明文案为：“这里记录兜兜拼音最近的新功能和小优化，也感谢每一位帮助它变得更好的朋友。”

## 页面结构

页面采用已确认的上下结构：

1. 上方是返回入口、引导短句、主标题和说明。
2. 下方是“最近更新”区域，显示更新总数和纵向时间线。
3. 更新记录区域使用固定的响应式高度和 `overflow-y: auto`，记录在区域内独立滚动，避免数据增多后无限拉长页面。
4. 每条记录依次展示日期、最新标记、标题、面向用户的更新内容和贡献人。
5. 只有第一条记录显示“最新”标记；数据按日期从新到旧维护。

视觉沿用主页现有的暖色纸张风格、圆角、边框和阴影，不引入新的设计系统或依赖。移动端缩小留白并保持单列，滚动区域仍可使用。

## 数据设计

新增 `src/data/changelog.ts`，导出类型和只读记录数组。单条记录结构为：

```ts
interface ChangelogEntry {
  date: string;
  title: string;
  items: readonly string[];
  contributors: readonly string[];
}
```

- `date` 使用可排序的 `YYYY-MM-DD` 格式，页面统一格式化为中文日期。
- `items` 支持一次发布记录多项用户可感知变化。
- `contributors` 默认包含“兜兜”，需要时追加其他贡献者。
- 首条数据使用当前日期 `2026-07-15`，标题为“更新动态看得见了”，内容为“新增更新日志页面，老师和家长可以查看最近的新功能、体验优化和贡献人”，默认贡献人为“兜兜”。push 前仍按确认流程检查是否需要调整文案或增加贡献者。

页面直接读取该数组，不使用网络请求、localStorage 或 Markdown 解析。

## 组件边界

- `src/routes/Changelog.tsx`：负责页面结构、日期显示和记录渲染。
- `src/data/changelog.ts`：只负责更新日志数据及其类型。
- `src/App.tsx`：注册 `/changelog` 路由。
- `src/routes/Home.tsx`：增加顶部入口。
- `src/styles/global.css`：增加页面和响应式样式，不修改打印专用 `print.css`。

首版不拆分单独的时间线卡片组件，因为只在一个页面使用，拆分会增加无收益的抽象。

## Push 前确认流程

在 `AGENTS.md` 的 Git 工作流中补充以下约束：

1. 准备 push 前，根据本次待发布差异生成一段面向老师、家长的推荐更新文案。
2. 向用户确认标题和更新内容。
3. 贡献人默认是“兜兜”，同时明确询问是否增加其他贡献者。
4. 用户确认后，将记录写入 `src/data/changelog.ts`，再执行最终验证和 push。
5. 不把内部重构、依赖调整、拼写修复等无用户感知的 Git 提交逐条展示。

该规则仅约束 push 前的发布流程；普通本地提交不强制新增一条更新日志。

## 边界与异常状态

- 数据为空时显示友好的空状态，不渲染时间线和“最新”标记。
- 记录内容由 TypeScript 类型和构建检查约束，不增加运行时数据校验。
- 日期无法解析不是预期输入；维护者必须使用规定格式。
- 不修改打印路由、历史记录协议、共享类型契约或依赖清单。

## 验证

- 为更新日志页补充 Vitest/Testing Library 测试，覆盖标题、返回链接、记录内容、贡献人和“最新”标记。
- 验证 `/changelog` 路由能够渲染，主页入口指向正确地址。
- 验证记录区域具有纵向滚动样式，并在窄屏下保持可读。
- 运行 `npm test` 和 `npm run build`。
- 实现完成后停在功能分支，等待用户运行 `npm run dev` 做本地视觉确认；未经确认不合并、不 push。
